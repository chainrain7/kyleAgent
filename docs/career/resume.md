## 1.5 RAG 检索管道(知识检索升级,全流程自研)

> - 为 runbook 检索自研**零依赖向量 RAG 管道**(分片→嵌入→召回→重排,纯标准库):
>   ATX 标题分片(800 字符上限/碎块合并/层级路径)→ **blake2b 特征哈希嵌入**
>   (CJK 单字+二元组、库级 IDF 加权、sublinear tf——禁用内建 hash 保证跨进程
>   确定性;可选 OpenAI 兼容嵌入端点带磁盘缓存)→ 余弦线性召回(库 <100 chunk,
>   ANN 过度设计)→ 混合重排(0.6 余弦 + 0.3 IDF 加权 Jaccard + 0.1 标题命中);
> - **评测驱动的模式决策**:36 条标注查询(字面/改写两类)离线实测三模式,
>   hybrid 在 Recall@1(0.889 vs 0.778)与改写查询维度显著占优,但 Recall@3
>   略逊(0.944 vs 0.972)——按预设门禁规则回退 keyword 为默认、hybrid 转
>   opt-in,数字如实写进文档而不是挑好看的;
> - 关键工程发现:哈希嵌入的桶碰撞噪声(cos 0.13+)会压过弱真命中,绝对阈值
>   不可行;改用**词面证据判定无匹配**(真实特征交集),桶碰撞无法伪造特征交集。

## 1.6 引擎级 Plan-Execute-Replan 闭环(Multi-agent 编排升级)

> - 把 planner→executor→reviewer 从"纯 prompt 一次性线性流程"升级为**引擎级
>   replan 闭环**:reviewer 末行输出结构化裁决 `VERDICT: ACHIEVED|PARTIAL|FAILED`,
>   引擎程序化解析(末尾 5 个非空行窗口内容错;无裁决保守回退 PARTIAL——
>   宁可多花一轮也不在未证实时宣布成功);未达成时上一轮计划全文 + 执行汇报
>   摘要(截断 4000 字)+ 审查发现自动回注 planner 出修订计划,直到达成或迭代
>   上限(`[orchestration] max_iterations`,默认 3);
> - **闭环不碰核心循环**:复用 spawn_agent 前景模式驱动三个子角色,闭环逻辑
>   收在新模块 `core/orchestrate/`,核心 ReAct loop 与事件协议零改动;循环内
>   严格串行(planner→executor→reviewer 逐个 await)是 cassette 顺序回放的
>   确定性前提,写成代码注释级不变量;
> - **评测实证**:新增 `orchestrate-replan` 评测任务——工作区是两级顺序闸门
>   检查器,第二道闸门的要求只在第一道修好后才在输出中暴露,"朴素一轮计划
>   必败";verify 断言两道闸门产物正确 + check.py 真跑通过 + 事件流含 ≥2 次
>   规划子代理启动(replan 实证),cassette 录制/回放进 CI 门禁。

## 2. 三分钟讲项目骨架

1. **一句话定位**(10s):"值班工程师半夜收到告警,我的系统自动查日志查指标定位根因,
   给出处置建议,危险操作必须他点批准才执行,完事自动出带证据链的报告。"
2. **为什么不是套壳**(30s):daemon+多客户端运行时、类型化 JSON-RPC 协议文档同源生成、
   事件流/trace 三层可观测——重点讲"审批为什么是一等公民"。
3. **评测方法论**(60s,最大差异点):三重断言的设计动机——回答对不对(关键词)、
   动手对不对(多重集合相等)、该不该动手(诊断类零变更);预授即审批的两层安全证据;
   首轮 80% 的失败怎么用 cassette 归因(排查瘫痪→runbook 补效率原则)。
4. **两个深挖模块**(60s):变更恢复语义(动作↔故障类型精确匹配、传导自动解除、
   表象与根因分离的 S7/S8);纯文件模拟环境的决策链(确定性/CI/可断言)。
5. **收尾**(20s):回放 2.5 秒 20/20、515 项测试、三平台 CI——工程收口。

## 3. 高频追问与答点

**Q: 为什么自己写运行时不用 LangChain/LangGraph?**
审批挂起(Future)、事件流外化、cassette 评测、durable 快照都要在循环层做一等公民;
框架把这些埋在回调里,改造成本高于自研,且教学/简历价值在引擎不在胶水。

**Q: 怎么证明 Agent 没有乱执行危险命令?**
两层:评测层变更调用集合与期望逐项相等(多/少都红);审批层不预授走真实 ASK
的集成测试(拒绝后状态不动)。零越权是断言出来的,不是"看起来没有"。

**Q: LLM 输出不稳定怎么办?**
cassette 录制/回放:顺序匹配(工具输出含时间戳,内容哈希必 miss);回放时工具在
隔离环境真实重执行,LLM 响应来自录制——CI 里 2.5 秒确定性回归 20 剧本。

**Q: 80% 到 100% 改了什么?会不会是过拟合?**
只改了知识库(runbook 效率原则)、goal 措辞、一个剧本的步数预算;断言一行没动。
改 runbook 影响的是所有用到该手册的剧本的先验知识——这是产品迭代不是过拟合;
且有回放门禁防止回归。

**Q: 模拟环境会不会太玩具?**
工程决策:纯文件换三件事——回放确定性(工具重执行结果一致)、Windows CI 可跑、
终态即文件可直接断言;对外只留 adapter 接口。演示价值在方法论不在环境仿真度。

**Q: 为什么 DeepSeek 不是 Claude?**
协议边界设计:消息格式以 Anthropic 形态为规范,兼容端点(Anthropic/OpenAI 双
provider)在边界内做翻译,核心循环零感知——换模型是配置不是改造。

**Q: RAG 为什么不用 embedding 模型/sentence-transformers?**
约束是零新依赖+离线确定性+三平台 CI 全绿。哈希嵌入(特征哈希+IDF+sublinear tf)
在 9 篇 runbook/29 chunk 的库规模上够用且逐位可复现;API 嵌入留了
OpenAICompatEmbedder(磁盘缓存,命中零网络)。更重要的设计:无匹配判定不依赖
分数(桶碰撞噪声实测 0.13+ 会压过弱真命中),依赖词面证据(特征交集不可伪造)。

**Q: hybrid 比 keyword 好为什么默认不用?**
评测说了一半真话:R@1/MRR/改写查询 hybrid 全面赢,但 Recall@3 差一条
(0.944 vs 0.972)。预设门禁规则是"R@3 ≥ keyword 才换默认"——按规则回退。
工程纪律大于叙事需求,且 hybrid 一行配置即可 opt-in。

## 4. 五分钟演示脚本

> 环境:`uv sync --extra webui` 已装;两个终端;浏览器开 http://127.0.0.1:8080

0. **开场**(30s):README 截图页——"这是值班工作台:左边告警队列和服务健康,
   右边诊断对话,每个危险操作都有审批卡。"
1. **注入故障**(30s):点"故障演练"→ 选 `orders-config-typo-errors` →
   告警卡出现、orders 变黄、err 8% 高亮。
2. **发起诊断**(30s):点告警卡 → 输入框自动填好标准处置指令 → Enter。
3. **观察诊断**(60s):Agent 并行查告警/状态/日志 → 工具行依次变绿 →
   给出根因(发布引入坏配置)。
4. **审批时刻**(60s,高潮):变更审批卡弹出,带影响面
   ("依赖方 gateway 健康检查将瞬时失败约 30s")→ 讲"这里人是一票否决权" → 按 y。
5. **恢复与报告**(60s):restart 执行、告警转 RESOLVED、服务回绿、
   侧栏出现报告 → 点开:结论/处置(含审批决策)/时间线/证据链。
6. **收口评测**(60s):`uv run python scripts/run_evals.py --suite oncall --replay`
   → 20/20, 2.5 秒 → "这个闭环在 CI 里每次提交都跑,谁改坏了值班行为直接红。"
