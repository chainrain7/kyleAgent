# 容量不足与流量激增(Capacity / Surge)

## 触发特征
- CPU/qps/p99 同步抬升,错误多为超时类(过载)
- 消费积压:consumer lag 持续增长(消费速率 < 生产速率),p99 抬升但错误率不高
- 缓存风暴:cache_hit_pct 骤降 + db_qps 暴涨(缓存失效把压力打到数据库)
- 场景:正常增长、促销(大促)、恶意流量(bot UA)

## 诊断步骤
1. metrics_query 看 qps 基线对比(×3 促销 / ×10 疑攻击)
2. logs_query 看流量构成(UA / 来源渠道)
3. 促销特征:多服务同步抬升、入口+核心链路都涨

## 处置
- scale_up 对应服务(消费积压扩消费服务;缓存风暴扩承压服务;大促扩入口+瓶颈)
- 恶意流量:扩容缓解 + 建议封禁/限流治本

## 效率原则
- 容量类故障看趋势即可下结论:两项以上指标(qps/lag/命中率/db_qps)同向偏离
  基线,就应果断扩容;不要穷尽式排查其他假设,也不要等待"更多证据"
- 注意:服务清单里没有的服务(如 orders-db)是外部依赖,查它只会返回 unknown

## 判断
- 全链路抬升=入口流量问题(扩 gateway+瓶颈服务);单服务抬升=自身容量
